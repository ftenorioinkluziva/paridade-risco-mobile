# Story 3.1: Fundação do cliente Pluggy e Sandbox

## User Story

Como backend do Paridade de Risco, quero acessar a API Pluggy exclusivamente pelo servidor e com Sandbox explícito, para preparar a migração de dados sem expor credenciais nem alterar a carteira manual atual.

## Scope

- Configuração server-only de ambiente, client ID e client secret.
- Proteção contra ativação acidental de produção.
- Cliente HTTP Pluggy com API Key cacheada e renovação após 401.
- Métodos de leitura para item, contas, investimentos, identidade, empréstimos e transações v2.
- Criação de Connect Token para a futura integração do widget.
- Validação estrutural das respostas externas sem registrar payload sensível.
- Testes com fetch mockado; nenhum teste depende de segredo commitado.

## Out of Scope

- Persistência em banco.
- Webhook.
- UI/widget.
- Substituição de `investment_funds` ou `transactions`.
- Rebalanceamento com dados Pluggy.

## Acceptance Criteria

1. Sem configuração, o cliente não pode ser criado para fazer chamadas externas e informa configuração ausente sem expor segredo.
2. O ambiente padrão é `sandbox`; produção exige opt-in explícito.
3. API Key é obtida via `POST /auth`, usada somente em headers server-side e renovada após expiração/401.
4. Connect Token é criado via `POST /connect_token` e retorna somente `accessToken` ao chamador interno.
5. Leituras usam `/items`, `/accounts`, `/investments`, `/identity`, `/loans` e `/v2/transactions` com query params explícitos.
6. Respostas incompatíveis e status HTTP não-2xx geram erro seguro, sem incluir API Key, client secret ou corpo bruto.
7. Testes cobrem Sandbox default, bloqueio de produção, cache/retry de API Key, headers, endpoints e paginação por cursor.
8. `npm run lint`, `npm run typecheck`, `npm test` e `npm run build:api` passam.

## Dev Notes

- A API Key tem ciclo curto e deve ser cacheada somente em memória do processo ou secret manager.

- O endpoint de transações usado é `/v2/transactions`; a rota legada não deve ser reintroduzida.
- O cliente é uma fronteira de infraestrutura. Normalização para o domínio financeiro fica nas stories seguintes.
