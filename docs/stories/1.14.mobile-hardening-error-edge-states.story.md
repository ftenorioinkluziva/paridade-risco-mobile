# Story 1.14: Hardening de erros e edge states mobile

## User Story

Como investidor individual,
Quero que o app trate falhas, textos longos e entradas invalidas de forma clara,
Para nao confundir dados ausentes com valores reais nem perder contexto durante uma decisao financeira.

## Objective

Executar `/impeccable harden apps/mobile`, cobrindo erros inline, retry, validacao de data e resiliencia visual contra textos longos.

## Scope

- Criar componente compartilhado para erro inline com acao opcional.
- Exibir erros persistentes e retry em Resumo e Rebalanceamento.
- Substituir alertas de login e transacao por mensagens inline persistentes.
- Validar data de transacao antes do envio.
- Melhorar truncamento/wrapping de textos longos em cards financeiros.

## Out of Scope

- Persistencia offline.
- Mudancas no contrato da API.
- Novos fluxos de autenticacao.

## Tasks

- [x] Criar componente de erro inline.
- [x] Aplicar erro/retry em Resumo e Rebalanceamento.
- [x] Aplicar erros inline em Login e Nova transacao.
- [x] Validar data de transacao.
- [x] Endurecer textos longos em cards.
- [x] Executar quality gates.

## Acceptance Criteria

1. Falhas de API em Resumo e Rebalanceamento aparecem inline com possibilidade de tentar novamente.
2. Login e nova transacao preservam input e mostram erro inline apos falha.
3. Data invalida nao gera `Invalid Date` nem payload invalido para API.
4. Nomes longos de ativos/fundos nao quebram a composicao principal dos cards.
5. Gates de qualidade sao executados e registrados.
