# Story 2.3: Hardening de autenticação MCP e API

## User Story

Como usuário autenticado, quero que minha identidade derive apenas de credenciais validadas e privadas, para impedir exposição de sessão e personificação.

## Status

Done

## Scope

- Disponibilizar MCP remoto em `/mcp` com `Authorization: Bearer`.
- Remover token de URLs, schemas públicos e logs.
- Remover `x-user-id` como fonte confiável de identidade e derivar usuário da sessão validada.
- Definir migração e retirada segura da rota legada.

## Out of Scope

- RBAC completo ou novo fluxo de cadastro.

## Acceptance Criteria

1. A rota canônica do MCP remoto não contém credencial na URL.
2. Token ausente, inválido ou expirado retorna erro canônico e status apropriado.
3. Alterar `x-user-id` não altera a identidade autorizada da requisição.
4. Logs de acesso e erro não contêm tokens ou credenciais.
5. A estratégia de migração e rollback da rota legada está documentada e testada.

## QA Results

### Review 2026-07-10 — Quinn (@qa)

**Gate: FAIL**

#### Rastreabilidade dos ACs

- AC1: PASS — a rota canônica é `POST /mcp` e recebe a sessão por `Authorization: Bearer`.
- AC2: FAIL — há teste apenas para token ausente. Token inválido e expirado não são exercitados; portanto, status e envelope canônico não estão comprovados nesses casos.
- AC3: FAIL — o código deixou de consumir/enviar `x-user-id`, mas não existe o teste de tentativa de personificação nem cobertura de usuário comum versus administrador exigidos pela story.
- AC4: FAIL — o logger da aplicação redige o caminho legado, porém, quando `ENABLE_LEGACY_MCP_TOKEN_ROUTE=true`, a credencial ainda trafega na URL e pode ser capturada por proxy, ingress ou observabilidade antes de chegar ao Hono. A implementação não garante a ausência de token nos logs de acesso externos.
- AC5: FAIL — a estratégia está documentada, mas o rollback habilitado, headers de depreciação/sunset e retirada segura não possuem teste.

#### Achados bloqueantes

1. **[CRITICAL][SECURITY] Rollback reintroduz credencial na URL.** `apps/remote-mcp/src/index.mjs` mantém `POST /:token/mcp`. A redaction no logger interno não protege logs de infraestrutura. O rollback deve preservar credencial privada, por exemplo por compatibilidade no endpoint sem segredo no path, ou exigir controles/redaction comprovados em toda a cadeia antes de ser considerado seguro.
2. **[HIGH][TEST] Cobertura de autenticação abaixo do contrato da story.** `apps/remote-mcp/test/auth.test.mjs` contém 3 testes, mas não cobre token inválido, token expirado, autenticação bem-sucedida, usuário comum, administrador, tentativa de personificação, rota legada habilitada, headers de migração ou inspeção de logs no caminho de erro/sucesso.
