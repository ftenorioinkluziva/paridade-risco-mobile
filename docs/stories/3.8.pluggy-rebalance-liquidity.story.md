# Story 3.8: Prévia de rebalanceamento Pluggy com liquidez

**Status:** Done  
**Epic:** [EPIC-3](../epics/epic-3-pluggy-carteira-real-e-saude-financeira.md)  
**Prioridade:** Critical  
**Dependência:** Story 3.7

## Objetivo

Usar a carteira Pluggy mapeada para calcular uma prévia de Paridade de Risco e verificar se o saldo bancário observado suporta os aportes necessários, sem executar ordens e sem substituir as rotas manuais.

## Escopo

- Criar rota e CLI de prévia Pluggy.
- Usar somente posições `MAPEADO` como carteira de risco.
- Usar `investedValue` como base da cesta e saldo bancário como liquidez separada.
- Calcular custo de aportes, proventos de reduções e caixa pós-plano.
- Bloquear a indicação de prontidão quando existirem posições não mapeadas ou perfil/cesta incompletos.

## Fora de escopo

- Enviar ordens para corretoras.
- Alterar `GET /api/rebalance/preview`.
- Tratar reserva, fatura e empréstimos como regras completas; isso pertence às stories 3.9/3.10.
- Contar limite ou saldo negativo de cartão como caixa.

## Critérios de aceitação

- [x] A prévia converte posições Pluggy mapeadas para o motor compartilhado de rebalanceamento.
- [x] A base de cálculo é o valor investido mapeado; contas bancárias ficam exclusivamente em `cashAvailable`.
- [x] O retorno informa `liquidityStatus`, `buyRequired`, `sellProceeds`, `postRebalanceCash` e `executionReady`.
- [x] Aportes acima da liquidez disponível ficam `INSUFICIENTE`, sem serem executados ou ocultados.
- [x] Posições não mapeadas geram advertência e impedem `executionReady`.
- [x] A rota exige sessão e a rota manual permanece inalterada.
- [x] CLI e HTTP não expõem `rawData` nem credenciais.
