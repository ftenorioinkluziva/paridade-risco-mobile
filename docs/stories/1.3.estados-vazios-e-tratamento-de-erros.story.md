# Story 1.3: Estados Vazios e Tratamento de Erros no Mobile

## User Story

Como usuario final,
Quero mensagens claras em estados vazios e falhas de rede,
Para entender o que fazer sem confusao.

## Objective

Melhorar UX resiliente em cenarios sem dados, falha de API e sessao invalida.

## Scope

- Padronizar UI para loading/empty/error nas telas principais
- Evitar erros em cascata no console por estados esperados
- Definir mensagem de acao para recuperacao (retry/login)

## Out of Scope

- Redesign visual amplo
- Internacionalizacao completa

## Tasks

- [ ] Catalogar estados vazios por tela
- [ ] Padronizar componentes de feedback de erro
- [ ] Adicionar acao de retry nos pontos criticos
- [ ] Reduzir ruido de erro esperado no console

## Acceptance Criteria

1. Cada tela core possui estado loading, empty e error explicitos
2. Erros 404 esperados nao aparecem como falha bloqueante no console
3. Usuario consegue recuperar fluxo com retry ou novo login
4. Mensagens sao objetivas e orientadas a acao

## Testing

- Simular API offline
- Simular 404 de recursos opcionais
- Simular expiracao de sessao
