# Story 2.4: Paridade entre CLI e MCPs

## User Story

Como consumidor de automações, quero encontrar as mesmas operações e semântica na CLI, MCP local e MCP remoto, para trocar de interface sem comportamento divergente.

## Status

Done

## 🤖 CodeRabbit Integration

> **CodeRabbit Integration**: Disabled
>
> CodeRabbit CLI is not enabled in `core-config.yaml`. Quality validation will use manual review process only.

## Scope

- Derivar definições dos adaptadores do catálogo canônico quando tecnicamente aplicável.
- Alinhar inputs, outputs e erros das operações equivalentes.
- Corrigir a divergência de `transaction_history.limit` e argumentos anunciados sem efeito.
- Manter adaptadores finos, sem duplicar regra de negócio.

## Out of Scope

- Adicionar comandos documentados inexistentes sem requisito aprovado.

## Tasks / Subtasks

- [x] Comparar automaticamente catálogos e schemas das interfaces (AC: 1, 4).
- [x] Remover duplicação evitável de definições de tools/comandos (AC: 1, 4).
- [x] Implementar ou retirar argumentos inconsistentes conforme o contrato canônico (AC: 2, 3).
- [x] Verificar exit codes, stderr e erros MCP estruturados (AC: 5).
- [x] Executar gates e atualizar a File List.

## Acceptance Criteria

1. Operações equivalentes possuem inputs, outputs e códigos de erro equivalentes.
2. `transaction_history.limit` tem o mesmo contrato e efeito em ambos os MCPs.
3. Nenhum adaptador anuncia argumento ignorado.
4. Teste de paridade falha se uma interface divergir do catálogo canônico.
5. CLI retorna exit code não zero e erro estruturado em falhas; MCP preserva código do erro canônico.

- Smokes de sucesso, input inválido e falha transitória.
- Gates constitucionais completos.

- Derivar contratos da fonte canônica da 2.1 sem mover regra de negócio aos adaptadores. Respeitar validação e autenticação entregues nas 2.2 e 2.3.
