# Story 4.6: Frescor das cotações BTG no front end

**Status:** Cancelled — obsolete; superseded by Story 4.7
**Epic:** EPIC-4 — Experiência Pluggy e decisão financeira  
**Executor:** @dev  
**Quality Gate:** @qa  

## Objetivo

Garantir que a tela `Cotações` mostre snapshots BTG recentes sem reutilizar
respostas HTTP antigas e reduzir o polling do front end para uma consulta por
minuto, que é suficiente para o monitoramento esperado.

## Disposição

Esta story não deve ser implementada ou revalidada. Seu escopo dependia de
`BTG_TRADE_DESK`, cuja dependência operacional foi removida pela Story 4.7.
O fluxo vigente usa Brapi/Yahoo e os parâmetros de monitoramento foram
posteriormente ajustados pela Story 6.1.

## História

**Como** usuário que acompanha cotações do BTG Trader Desk,  
**quero** que a tela atualize os snapshots reais sem cache antigo e consulte o
backend a cada 1 minuto,  
**para** visualizar dados atuais sem gerar consultas excessivas.

## Escopo

- Ajustar a consulta client-side de `/api/assets/prices?source=BTG_TRADE_DESK`
  para não reutilizar resposta em cache (`cache: "no-store"`).
- Fazer a rota de preços BTG responder com política HTTP que impeça cache
  (`Cache-Control: no-store, max-age=0`).
- Alterar o intervalo automático da tela `Cotações` de 5 segundos para
  `60_000` ms (1 minuto).
- Manter o botão `Atualizar agora` funcionando imediatamente, sem aguardar o
  intervalo automático.

## Fora de escopo

- Alterar a bridge local `read-rtd.ps1` ou a frequência de leitura do RTD.
- Alterar o intervalo de ingestão no backend, banco de dados ou schedulers.
- Criar WebSocket, SSE ou atualização em tempo real subminuto.

## Dev Notes

- A tela client-side está em `apps/api/src/app/cotacoes/page.tsx`.
- O endpoint BTG está em `apps/api/src/app/api/assets/prices/route.ts`.
- O fluxo BTG seleciona a cotação mais recente de `live_quotes` por ativo,
  ordenando `received_at DESC`.
- O campo `price` da resposta é derivado de `live_quotes.last`, que é preenchido
  pela rota `POST /api/integrations/profit/quotes` a partir de
  `QUOTE.LAST_TRADE_PRICE`.
- A mudança deve permanecer limitada ao comportamento de atualização do front e
  à política de cache HTTP; não deve alterar persistência ou autenticação.

## Testing

- Teste de rota: verificar que o fluxo `source=BTG_TRADE_DESK` mantém o payload
  atual e devolve `Cache-Control: no-store, max-age=0`.
- Teste de componente/browser: confirmar que o timer usa 60 segundos e que o
  refetch manual atualiza a lista.
- Validação manual: consultar a API, aguardar um novo `received_at` da bridge e
  confirmar que a tela exibe o snapshot novo após o ciclo ou após `Atualizar
  agora`.
