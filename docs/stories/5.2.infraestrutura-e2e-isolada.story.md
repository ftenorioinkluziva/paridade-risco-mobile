## Story

**Como** equipe de desenvolvimento,
**quero** uma infraestrutura E2E determinística e isolada,
**para que** regressões dos fluxos críticos sejam detectadas antes do deploy.

## Acceptance Criteria

1. Playwright está configurado para Chromium desktop `1440x900` e mobile `390x844`, com base URL configurável.
2. A suíte sobe contra Docker Compose local/CI e aguarda healthcheck em vez de usar sleeps fixos.
3. Um usuário E2E exclusivo é criado por seed/factory, com perfil e cesta válidos, sem usar conta compartilhada de produção.
4. Dados criados pelos testes têm namespace próprio e limpeza idempotente, inclusive após falha.
5. Scheduler e integrações externas não tornam a suíte flakey; dependências não determinísticas são desativadas ou controladas no ambiente E2E.
6. Trace, screenshot e vídeo são preservados em falha, sem expor senha, cookie, token ou chave.
7. Existe um comando único local e um gate de CI documentados para executar a suíte smoke.
8. WebKit mobile fica configurado como projeto opcional/agendado, sem bloquear o gate rápido inicial.

## Dev Notes

- Não há harness Playwright/Cypress no baseline; a homologação atual é manual em `docs/roadmap/homologacao-4-telas-e2e-2026-04-10.md`.
- A aplicação web está em `apps/api`; use o servidor Next.js e o PostgreSQL do Compose existente.
- Não acoplar a suíte à ordem dos testes. Cada teste deve conseguir preparar e limpar seu estado.
- Seletores devem privilegiar role/label/test-id estável, nunca texto acidental ou estrutura CSS.
- Segredos E2E pertencem ao ambiente local/CI e nunca aos artefatos.
