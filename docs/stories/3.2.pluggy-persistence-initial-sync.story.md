# Story 3.2: Persistência Pluggy e sincronização inicial Sandbox

## User Story

Como usuário do Paridade de Risco, quero que os dados do meu item Pluggy sejam persistidos com origem e data de observação, para que o app possa construir uma carteira real sem perder rastreabilidade ou duplicar registros em novas sincronizações.

## Scope

- Persistir conexões Pluggy, contas, investimentos, empréstimos, transações e execuções de sincronização.
- Preservar o payload bruto sanitizado de cada recurso para auditoria e futura normalização.
- Associar os registros ao usuário local e ao `itemId` Pluggy.
- Implementar upsert por identificador externo estável.
- Sincronizar o item Sandbox pela CLI, incluindo todas as páginas de transações v2.
- Manter a carteira manual atual como fonte ativa; esta story não altera `/api/portfolio/summary`.

## Out of Scope

- Widget/UI para conectar novas instituições.
- Webhooks.
- Mapeamento para ativos e cestas.
- Substituição do cálculo de rebalanceamento.
- Regras de cartão, fluxo de caixa ou saúde financeira.

## Acceptance Criteria

1. A migração cria tabelas Pluggy com chaves externas únicas e vínculo com usuário/conexão.
2. A sincronização Sandbox cria ou atualiza a conexão e os recursos sem duplicar registros quando executada novamente.
3. A sincronização percorre o cursor `next` de transações até o fim.
4. Cada registro mantém `source_*`, `raw_data`, `observed_at` e status suficiente para auditoria.
5. Um erro de um recurso encerra a execução com status de falha sem apagar o último snapshot válido.
6. O comando CLI não imprime API Key, Client Secret ou payload financeiro bruto.
7. O resumo manual e as telas existentes permanecem inalterados.
8. `npm run db:generate`, `npm run db:migrate`, `npm run typecheck:api`, `npm run lint:api` e os testes relevantes passam.

## Dev Notes

- O sincronizador é CLI-first e não depende da UI.
- O `userId` da primeira execução Sandbox será fornecido por variável `PLUGGY_SYNC_USER_ID`; não se deve assumir o primeiro usuário do banco.
- Transações bancárias/cartão do Pluggy não serão convertidas em `transactions` manuais de compra/venda.
- Ausência de empréstimos ou produto não suportado é persistida como resultado da sincronização, não como saldo zero.
