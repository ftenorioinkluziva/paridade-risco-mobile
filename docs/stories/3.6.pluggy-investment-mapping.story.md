# Story 3.6: Mapeamento estratégico dos investimentos Pluggy

**Status:** Done  
**Epic:** [EPIC-3](../epics/epic-3-pluggy-carteira-real-e-saude-financeira.md)  
**Prioridade:** Critical  
**Dependência:** Story 3.3

## Objetivo

Permitir que o usuário aprove explicitamente o vínculo entre uma posição observada pelo Pluggy e um ativo estratégico do Paridade de Risco. A aprovação deve ser persistida, auditável e reversível, sem alterar ainda o resumo da carteira ou o rebalanceamento.

## Escopo

- Persistir um mapeamento por usuário, investimento Pluggy e ativo local.
- Promover `SUGERIDO` para `MAPEADO` somente após uma ação explícita.
- Permitir substituir ou remover o vínculo.
- Expor o vínculo no contrato da projeção normalizada.
- Definir o contrato mínimo que o futuro `PortfolioProvider` usará, sem trocar o provider atual.

## Fora de escopo

- Alterar `GET /api/portfolio/summary` ou `/api/rebalance/preview`.
- Mapear automaticamente posições sem identificador exato.
- Considerar cartão, conta corrente ou limite de crédito como posição estratégica.
- Executar ordens ou alterar dados do Pluggy.

## Critérios de aceitação

- [x] Só é possível mapear investimento e ativo pertencentes ao usuário/ambiente válido.
- [x] O vínculo persiste `userId`, `pluggyInvestmentId`, `assetId`, status `MAPEADO`, data de aprovação e timestamps.
- [x] Repetir o mesmo pedido atualiza o vínculo sem duplicar registros.
- [x] Remover o vínculo retorna a posição para `SUGERIDO` quando houver candidato exato, ou `PENDENTE` caso contrário.
- [x] A projeção não expõe `rawData` e diferencia `MAPEADO` de `SUGERIDO`.
- [x] A API de escrita usa validação de payload e suporte a `Idempotency-Key`.
- [x] O provider atual permanece manual; nenhuma rota existente muda de fonte nesta story.

## Contrato HTTP

- `POST /api/integrations/pluggy/mappings` com `{ "investmentId": "...", "assetId": "..." }` cria ou substitui o vínculo.
- `DELETE /api/integrations/pluggy/mappings/:investmentId` remove o vínculo do investimento.
- `GET /api/integrations/pluggy/projection` passa a reportar `mappingStatus: "MAPEADO"` após aprovação.
