#### Anti-Patterns Verdict

**LLM assessment:** This no longer reads like a generic AI dashboard. The new `RebalanceDecisionCard` gives the product a specific point of view: the app answers "preciso rebalancear?" before showing portfolio details. #### Overall Impression

The app is now directionally aligned with `PRODUCT.md`: decision first, metrics second. The biggest opportunity is to remove the remaining ambiguity around what happens after the rebalance recommendation: "Use this plan" is visible, but the interface does not yet explain whether it executes trades, saves a plan, or just confirms intent.

#### What's Working

- The decision card in `apps/mobile/src/components/RebalanceDecisionCard.tsx` creates a strong north star: status, title, detail, metrics, and first actions in one surface.
- Color semantics mostly follow the new design system: buy/sell labels accompany color, and green is tied to action/positive state.
- The transaction flow has useful inline validation and a preview, which supports low-friction mobile operation.

#### Priority Issues

**[P1] Ambiguous final action in Rebalanceamento**

**Why it matters:** A high-stakes financial screen cannot end with an unclear command. `PrimaryButton label="Usar este plano"` appears after the suggested actions, but there is no visible explanation of whether this places orders, saves a plan, copies instructions, or simply acknowledges the recommendation.

**Fix:** Rename the action to the actual behavior. If no execution exists yet, use "Salvar plano" or "Marcar como revisado" only if implemented; otherwise remove the button and replace it with a passive note such as "Use as ordens acima na sua corretora." Add a confirmation or next-step state when it becomes actionable.

**Suggested command:** `/impeccable clarify apps/mobile/src/screens/RebalanceScreen.tsx`

**[P1] Rebalance screen repeats decision metrics too soon**

**Why it matters:** The decision card already shows desvio, custo and saldo apos. Immediately repeating invested value, cash, base, cost and post-rebalance cash makes the top half feel less minimal and forces the user to parse the same decision twice.

**Fix:** Collapse the secondary metrics into a compact "Detalhes do calculo" section below the actions, or show only `base de calculo` and `caixa disponivel` as supporting context. Keep the first viewport focused on status and buy/sell actions.

**Suggested command:** `/impeccable distill apps/mobile/src/screens/RebalanceScreen.tsx`

**[P2] Icon-only bottom navigation hurts recognition**

**Why it matters:** `tabBarLabel: () => null` makes experienced users faster but forces first-time users to memorize icons. For an investor checking money on a phone, hidden labels increase hesitation.

**Fix:** Show compact labels, at least for the active tab, or add accessible labels/tooltips if visual labels are intentionally hidden. Keep icons, but do not rely on icon recognition alone.

**Suggested command:** `/impeccable clarify apps/mobile/src/navigation/AppNavigator.tsx`

**[P2] Loading/error state is uneven across async screens**

**Why it matters:** The decision card says "Calculando", but secondary cards in Rebalanceamento fall back to `R$ 0,00`. API errors are captured by hooks, but the screens do not consistently surface those errors inline. Users may mistake missing data for real zero balances.

**Fix:** Add shared loading/error primitives for portfolio and rebalance data. While loading, show skeleton/placeholder text rather than zero values. On error, show a persistent inline recovery block with retry.

**Suggested command:** `/impeccable harden apps/mobile`

**[P2] Transaction asset picker exceeds the minimal-choice rule**

**Why it matters:** The new transaction flow can show 8 asset choices at once. That is above the <=4 decision target from the cognitive-load checklist and can feel like a list scan rather than a guided choice.

**Fix:** Show the top 4 matches, then a "ver mais resultados" expansion, or prioritize exact ticker match plus 3 likely matches. Keep the selected ticker summary visible.

**Suggested command:** `/impeccable distill apps/mobile/src/screens/NewTransactionScreen.tsx`

#### Persona Red Flags

**Jordan (First-Timer):** The core rebalance decision is now understandable, but bottom navigation is icon-only. Jordan can read "Sua carteira precisa de rebalanceamento", then hesitate about where "Fundos", "Transacoes" or "Cestas" live because the labels are hidden.

**Sam (Accessibility-Dependent User):** Color is usually paired with labels, which is good. Gaps remain around focus/error communication: native alerts are transient, API errors are not consistently shown inline, and icon-only tabs need accessible labels verified.

**Casey (Distracted Mobile User):** The decision card is strong for interrupted mobile use. The problem is the Rebalance screen's top stack: decision card plus repeated metrics plus action list means Casey may need to scroll before seeing the complete order set and next step.

**Project-specific, Individual Investor "Felipe":** This user wants one answer: rebalance or not. The app now gives that answer, but the CTA "Usar este plano" creates legal/operational ambiguity. If the app cannot execute trades, the UI must not imply it can.

#### Minor Observations

- `RebalanceDecisionCard` receives `isLoading` from portfolio loading on Overview, not from `useRebalancePreview`, so the card can say it is done before rebalance data has arrived.
- `RebalanceDecisionCard` uses text like "Saldo apos" without accent due ASCII convention, but the concept may need a short explanation.
- `NewTransactionScreen` uses a free-text date instead of a constrained picker or validated date helper.
- `LoginScreen` uses `Alert.alert` for failed login instead of an inline error that remains visible.

#### Questions to Consider

- Should the tab bar favor speed for repeat users or clarity for first-time investors?
